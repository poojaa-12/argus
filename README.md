# Argus

Argus is a reliability-first agent runtime. The original linear orchestrator still
runs deterministic ReAct-style plans with retries and fallbacks. This tree also
includes a **Deep Research & Operator** runtime: a cyclic LangGraph state machine
with parallel researcher fan-out, Human-in-the-Loop interrupts, Redis/Postgres
persistence, token-budget compression, and an LLM-as-judge eval harness.

The **Deal Intake** vertical is a last-mile private-markets deployment on that
runtime: CIM/teaser extract → thesis score → associate approval → DealCloud /
SharePoint write. See [playbooks/acme-capital.md](playbooks/acme-capital.md).

## Reliability evals (linear orchestrator)

```bash
PYTHONPATH=. python3 -m argus.evals.report
```

This writes `eval_report.json` with:

- Full-suite baseline vs reliability-enabled success rate (50 tasks).
- Injected-failure baseline vs reliability-enabled recovery rate (20 tasks).

The current deterministic suites produce:

- Main suite: `39/50` (78.0%) -> `46/50` (92.0%).
- Failure injection: `12/20` (60.0%) -> `18/20` (90.0%).

That **92%** is *task success with retry/fallback policy on*, not tool-selection
accuracy.

Relative recovery uplift: `(with_reliability_rate - baseline_rate) / baseline_rate`.
Example: baseline `0.60`, reliability `0.90`, relative uplift `0.50` (50%).

## Deep Research judge evals

```bash
PYTHONPATH=. python3 -m argus.evals.judge.report
```

This writes `eval_report_judge.json` for 50 frozen multi-step queries. The
current scripted-provider run produces:

| metric | value |
|---|---|
| Tool selection accuracy | 50/50 (100.0%) |
| Hallucination rate | 0.0% |
| Mean LLM calls / task | 5.06 |
| Token reduction vs bloated scratchpad | 97.7% |

Those numbers are generated by the harness (`tests/fixtures/judge_report_summary.json`).
Do not copy the reliability 92% into this table. Token reduction is measured on
injected oversized tool payloads at an 80% context-window trigger, not on live
traffic.

## Graph runtime

```bash
make up          # Redis + Postgres (optional)
make api         # FastAPI on :8080
```

- `POST /v1/runs` start a graph run
- `GET /v1/runs/{id}/state` inspect checkpoint / pending destructive action
- `POST /v1/runs/{id}/resume` supply human feedback and continue from the interrupt
- `WS /v1/runs/{id}/events` stream run events

Destructive tools (`db_write`, `delete_record`, `crm_upsert`) and ambiguous plans interrupt
before the operator acts. Checkpoints are JSON blobs in Redis when
`ARGUS_REDIS_URL` is reachable, otherwise in-process memory. Run records live in
Postgres when `ARGUS_DATABASE_URL` is set, otherwise SQLite/memory.

Unit tests use MemorySaver/local graph + in-memory/SQLite stores. Integration
tests require `ARGUS_INTEGRATION=1` after `make up`.


## Token compression

Before each model/policy node, Argus counts scratchpad tokens (tiktoken
`cl100k_base`, with a `len/4` fallback). At 80% of `ARGUS_CONTEXT_WINDOW` it
summarizes **tool outputs only**. `task` and `system_instructions` are pinned.

## Dual execution modes

- **CI / default:** `ARGUS_LLM_PROVIDER=scripted` — no API keys.
- **Live (optional):** `ARGUS_LLM_PROVIDER=openai` and `OPENAI_API_KEY` overlay
  LangChain chat models on the same graph.

Operator tool calls still go through `Orchestrator._call_step` and the existing
retry/fallback policy.

## Observability

Graph nodes emit OpenTelemetry spans (`argus.graph.*`) and token counters
`argus.tokens.before` / `argus.tokens.after`. The linear orchestrator still uses
the pluggable `StructuredLogger` / `MetricsExporter` interfaces.

See `.env.example` for configuration.
